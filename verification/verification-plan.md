# 技术验证与质量验收计划（待执行）

## 1. 目标与范围

本计划把 ADR-106 的“可验证规格”转化为研发前的认证清单。**当前没有执行任何 PoC 或测试**，下述用例是设计好的验收要求，并不代表已有结果。

## 2. P0 验证序列

### P0-A · 基础持久性与 RTO/RPO

- 输入矩阵：数据库产品/版本、驱动、框架版本、标准/HA 部署。
- 故障注入：应用进程退出、主数据库节点损毁、旧主网络分区、同步副本不可用、提交确认响应丢失、人工/自动切换。
- 检查点：已经确认的关键事务、关键审计、Outbox 与稳定请求 ID 一致；不能达到持久性保证时关键新写入不返回成功。
- 目标：标准 RTO≤4h、HA RTO≤15m；关键事务在认证故障范围内零已确认提交丢失。
- 验证状态：待执行；所有组合测试结果独立记录。

### P0-B · 真实四数据库契约

- PostgreSQL、SQL Server、MySQL、达梦逐库验证：事务与数据类型、迁移与重跑、隔离、Outbox、任务租约与幂等。
- 达梦先验证 Kysely Dialect + dmdb；不通过时按 ADR-123 评估受控 dmdb/SQL 适配。
- 不能以 CI 编译成功或数据库连通性替代正式合同测试。

### P0-C · 插件与 AI 安全

- 插件签名和授权、文件/网络/数据库最小权限、停用后禁止新调用、任务检查点及错误恢复。
- GraphQL 多实例 Schema 发布、命名冲突拒绝、向后兼容和停用响应语义。
- Agent 执行前身份/资源版本/审批/幂等复核；撤销长期授权后阻止后续执行。
- 用跨工厂越权及关键状态绕过调用等负向场景强制触发 CI 拒绝。

## 3. P1 容量与工程体验

- 建立只供测试的参考业务模块，不引入生产业务范围。
- 基准变量：硬件、数据库及驱动版本、数据体量、并发请求、Worker 数量、事件产生速率与离线持续时间。
- 指标：GraphQL Query/Mutation P95、成功率、关键事务提交延迟、任务积压恢复、Outbox 事件延迟、同步吞吐及峰值资源占用。
- 所有具体指标数值需要后续评审确认，不得在未测量前填为已达成。

## 4. 验证结果记录格式

每一个认证组合应记录：

1. `case_id`、目标 ADR、场景前置条件及测试数据集。
2. 系统版本、数据库及驱动版本、OS/容器和故障域说明。
3. 操作步骤、起止时间、观测指标和结果证据。
4. 通过/失败结论、缺陷与风险、负责人与替代路径。
5. 复测结果、认证有效范围和过期/失效条件。

## 5. 与架构阶段的关系

本文件只是验证计划；进入工程实现或正式认证应另外取得相应阶段授权。根据 ADR-106，架构设计收敛并不意味着所有技术测试必须现在完成。
