# 签名插件包与运行时契约 · Draft V0.2

**ADR：** 017～018、024～025、032～034、042～043、048、055、078～083、088～089、093、096、104～105、110～111、130。

## 交付对象

不可变签名包须一次性描述服务器组件、GraphQL/Action 公开能力、UI 组件、任务处理器及数据迁移。包含稳定 `pluginId`、`version`、`digest`、`signature`、`publisher`、`sdkRange`、`dependencies`、`databaseSupport`、`migrations`、`capabilities`、`taskHandlers`、`graphqlExports` 等语义。具体序列化格式与密钥基础设施尚未冻结。

## 安装/停用的检查点

1. 验签及散列一致，发布者获信任；版本兼容、依赖无环、数据库匹配。
2. 权限能力由管理员明确授予；预检查数据库迁移，不在生产热安装时执行破坏性变更。
3. 生成并验证 GraphQL Schema 快照和动作目录快照，确认发布代际对应同一插件版本。
4. 激活期间由受控入口切流；在高可用节点渐进发布、观察就绪和客户端兼容。
5. 停用先撤销新入口，已开始任务完成或保存 checkpoint，不直接删除旧任务；Query/Mutation 兼容窗口内返回明确错误。
6. 回退只能在数据结构兼容且权限允许时进行；代码回退与数据修复不可混同。

## 信任和隔离

- 同进程插件视为可信；逻辑停用不代表物理卸载代码。
- 低信任插件必须进程/容器隔离，包含 CPU、内存、网络、文件、数据库访问控制；迁移身份与运行身份分离。
- 关键生产表写入必须走受控业务动作；低信任 UI 必须隔离，不接触宿主高权限令牌。

## 核心拒绝用例

非法签名、兼容范围不匹配、权限扩大未批准、同名 Schema、数据库迁移冲突、停用后新任务领取、插件直接关键表写入、iframe 越界消息，均必须拒绝并留下追踪证据。
