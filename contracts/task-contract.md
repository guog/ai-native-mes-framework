# 持久化任务契约 · Draft V0.2

**ADR：** 034、045、074、082、092、118、122。

## 任务身份与状态

必须具有稳定任务 ID、模块/插件和处理器版本、所属工厂、任务 Schema 版本、尝试次数、下一可领取时间、租约、fencing/状态版本、checkpoint、幂等标识、审计关联及错误分类。具体字段名可在设计评审中统一。

## 执行语义

- Worker 独立进程，使用主业务数据库任务表；至少一次执行，处理器必须幂等或可恢复。
- 原子领取、续约、完成判定与错误分类由每数据库认证实现。租约失效的旧 Worker 不能再推进任务权威状态。
- 进程意外退出后按租约回收并核查副作用与请求 ID；重试必须受指数退避或等效预算及隔离策略约束。
- 插件 draining 后不领取新任务；旧版本任务不能被不兼容处理器执行，必要时持久 checkpoint 或等待恢复。

## 验收

双 Worker 并发领取、租约过期后旧 Worker 迟到、主库切换、任务写完成前宕机、处理器升级以及死信恢复。四种数据库需独立验证实际锁/事务行为。
