# 可靠事件与跨站点同步契约 · Draft V0.2

**ADR：** 023、030～031、040～041、049～051、061、097、099。

## 事件信封最低语义

`eventId`、`eventType`、`schemaVersion`、`aggregateId`、`aggregateSequence`、`sourceFactoryId`、`authority`、`occurredAt`、`correlationId`、`causationId`、`payload`、`payloadHash`。名称是表达示例。

- 业务事务与 Outbox 原子提交，随后异步投递；传输保证至少一次，接收端按事件 ID 幂等记录。
- 顺序保证基于必要的业务实体序列；不要求全局串行。
- 对数据变更拥有唯一权威源；非权威侧向权威侧提交业务变更请求，不做最后写入者获胜的冲突覆盖。
- 集团指令包含稳定 command ID、有效期、目标工厂、指令版本；工厂本地验收并回传接受、拒绝、执行成功/失败状态。

## 断网与补传

检查点表示目的端持久确认处理的顺序位置，不能仅记“网络发送成功”；断网事件持久积压，按照业务量和最大断网时间规划容量并报警，关键事件不得静默丢弃。

恢复时进行版本协商、检查点补传、必要快照与业务对账；不得无授权使用集团快照直接覆盖工厂权威数据。对账不通过转人工修复并留下审计。

## 验收

同一事件重发/乱序、断网多天、中心旧版本、检查点缺口、指令过期、恢复时积压压力：最终不重复业务效果、不静默丢失关键事件、有可审计失败/补偿记录。
