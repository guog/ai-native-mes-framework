# 模块公开契约规范 · Draft V0.2

**关联 ADR：** 058～062、073、080、087。此文中的标识及字段名是建议的机器可读表现形式，未实施，不修改 ADR。

## 必填语义

1. `moduleId`：组织范围内稳定唯一；`moduleVersion`、`sdkRange`、`hostRange`：支持范围。
2. `owners`：模块负责人、代码仓库及故障支持渠道；`trustClass`：受认证的信任级别。
3. `dependencies`：公开模块 ID + 兼容版本区间；**无环**，禁止源码级跨模块私有 import。
4. `exports`：公开服务/动作/查询/事件的可版本化引用；`imports`：仅允许依赖公开接口。
5. `dataOwnership`：拥有的对象范围；禁止跨模块直接访问私有表。
6. `requiredCapabilities`：文件、网络、数据库、调用权限及任务预算，必须在授权层映射。
7. `lifecycle`：验证/初始化/就绪/激活/排空/停用/失败观察点。

## 调用纪律

- 同步调用适用于可用性要求明确的短操作，服务端需要统一超时、取消及请求上下文；避免隐式多层同步调用形成环。
- 可靠业务事件具有唯一 ID/版本，写入业务数据库 Outbox；轻量进程内通知不必冒充持久事件。
- 跨模块事务默认分离；必要时仅可信同数据库同事务上下文参与，隔离插件只能通过 API 或异步协调。
- 每项导出的写操作必须拥有业务动作契约，不因 Resolver 自带功能而自动获得能力。

## 自动验收

- 静态依赖图无环；非公开 import 阻断；导出名称唯一；SDK 兼容范围校验。
- 生命周期停止新流量、在途任务安全处理；模块失败令依赖功能安全不可用，无关模块保活。
- 标识、状态及合规测试应可被 Code Agent 和 CI 读取。
