# 第 1 章 · 总体说明

## 1.1 建设对象

本项目建设的是**面向生产型企业的现代化 MES 技术基础框架**，供内部研发团队及客户项目开发工业生产管理应用。它不是包含订单、工单、报工、BOM、工艺路线和质量业务的完整 MES 成品。框架为不同项目提供稳定公共技术能力、扩展约束与工程规范。

**适用场景：**
- 单工厂在现场独立部署，自主运行和管理本地生产数据。
- 同一客户集团下多工厂自治运行，并以事件、状态快照和业务指令与集团层交换数据。
- 不同客户企业独立部署并独立维护发布节奏。
- 中小并发、生产关键业务；性能目标按参考负载分级认证，不以互联网高并发作为预设前提。

**非目标：**
- 不预设电子制造、装备、食品等某个行业的生产领域模型。
- 不要求所有客户购买或部署中央 AI 服务。
- 不把客户定制化全部变成运行时低代码解释器。
- 不把微服务、Kubernetes、跨机房自动故障切换作为默认架构。
- 不让 AI 绕过业务动作、权限、审批、事务与审计直接修改生产状态。

## 1.2 核心目标与优先级

1. **正确性与可恢复性**：生产关键事务满足零已确认提交丢失的架构目标；持久性无法保证时拒绝确认新的关键写入。故障覆盖、RTO、HA 切换须认证。
2. **简单**：模块化单体、最小稳定内核、可选官方技术模块；轻量 Linux + Docker；后台持久化任务默认主业务库，独立 Worker。
3. **可扩展**：版本化公开模块契约与签名不可变插件包；信任级别与最小权限；动态安装和逻辑停用；不要求任意同进程 JS 被完全卸载。
4. **AI Native**：开发阶段面向 Code Agent 的机器可读规格、质量门禁；产品阶段独立 AI Runtime 通过受控动作执行业务；扩展阶段 AI 可生成代码但不能跳过生产批准。
5. **数据库可移植**：每实例一种主数据库，正式目标 PostgreSQL / SQL Server / MySQL / 达梦，框架及官方插件接受真实数据库认证测试。

### 质量属性冲突的统一处理

- 零已确认生产事务丢失与持续写入冲突时，以正确性优先，安全降级而不是默默降低持久性。
- 插件动态扩展与安全隔离冲突时，将客户/低信任插件放入独立隔离执行环境。
- 四数据库兼容与 ORM 统一性冲突时，保留适配器及受控 SQL 的选择，不牺牲事务正确性。
- 工厂自治与集团集中管理冲突时，以本地生产事务权威为先，集团通过可重试的业务指令协调。

## 1.3 产品边界

### 由框架统一约束的公共技术能力

- 模块元数据、注册、公开契约、依赖图与生命周期。
- 业务动作注册和受控执行机制；GraphQL Schema 组合与版本发布。
- 身份权限、安全审计、任务、可靠消息等能力的官方技术模块或基础契约。
- 持久化抽象、跨数据库迁移和事务边界规范。
- 插件签发、安装、授权、运行、停用及版本兼容机制。
- 前端应用壳、可信 UI 插槽、低信任 UI 隔离及声明式展示配置。
- AI Runtime 与框架的受控协议和生产故障降级边界。
- 质量属性的测试契约与认证要求。

### 由 MES 业务模块承担

- 工单、生产执行、库存、检验、追溯、车间排程等业务实体和规则。
- 行业/工厂独有的工艺、业务动作、页面、迁移和测试。
- 数据的领域级所有权、跨工厂具体同步项目和数据分类。

### 由外部基础设施承担

- 设备协议采集：独立工业网关/适配器；MES 仅定义标准集成契约。
- 数据库节点选主、仲裁和 fencing：经过认证的数据库高可用或存储基础设施。
- 模型推理与 Agent 编排：独立 AI Runtime；模型接入可替换，MES 核心离线仍需工作。

## 1.4 强制不变量

- 对关键业务动作，认证、授权、审批、参数/资源版本检查和幂等校验不得被 GraphQL/REST/MCP/Agent 任一入口绕过。
- 跨模块禁止直接访问私有实现和私有业务表；可信模块必要时可经公开契约共享同本地事务。
- 工厂生产业务不得把集团中心在线状态作为提交前提。
- 已停用插件不得继续执行其业务动作；保留兼容期 Schema 不代表仍能调用业务能力。
- 客户插件的签名仅证明包来源/完整性，不代表拥有任何运行时高权限。
- 所有生产插件安装/升级必须有授权人员最终批准。

## 1.5 可用性与验证状态

- ADR 仅证明设计决策得到确认，不能作为生产级测试结果。
- 目前没有可声称的数据库高可用认证矩阵、四库合同测试通过报告或性能实测数值。
- 第一批交付仅是架构规格与风险验证规划，不包含框架源代码、数据库实体或发布配置。
