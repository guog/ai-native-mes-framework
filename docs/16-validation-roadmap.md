# 第 16 章 · 质量验证、风险与实施路线

**状态：** 验证计划草案，非测试结果。**ADR：** 037、046～047、057、087、098～099、106～109、112、125～130。

## 16.1 架构验收策略

规格书面向后续工程建设，当前只定义可验证约束，不执行 PoC、CI 或生产故障注入。主质量证明来自可追溯的 **ADR → 可验收要求 → 测试场景 → 实测证据 → 认证条目**，不可用设计图替代。

## 16.2 P0 验证优先序列

1. **关键事务持久性**：对单服务器/存储故障、丢失同步副本、提交响应丢失、主节点损毁、网络分区、脑裂风险进行故障注入。核验已确认关键业务数据、审计、执行结果、Outbox 保持一致；不满足保护时拒绝新的关键写入。
2. **四数据库契约**：数据库版本和驱动逐个测试事务、数据类型、迁移、幂等、租约/Worker、Outbox、审计；达梦 Dialect 未通过则按 ADR-123 验证备用适配。
3. **安全负向门禁**：插件越权访问文件/网络/数据库、跨工厂读取、绕过关键业务动作、Agent 审批参数变更、权限撤销、过期任务重放均应拒绝并产生证据。
4. **GraphQL/插件发布**：新 Schema 原子快照、HA 节点逐步切换、旧客户端兼容、插件停用错误语义、在途请求/任务安全完成或检查点恢复。

## 16.3 P1 性能与运营验收

- 参考测试业务模块覆盖典型 GraphQL 读取、关键事务写入、审计、Worker、Outbox、工厂/集团同步；测试所用业务仅为验证，不进入核心框架业务产品。
- 报告硬件、数据量、数据库版本、容器环境、并发数、请求比、持续时间；观测 P50/P95/P99 延迟、错误率、租约失效、任务积压恢复、同步吞吐及磁盘空间。
- 按低并发典型使用与短时批量负载分级定义可达验收目标。**尚未批准具体并发与 P95 数值**；不得宣称达标。
- 长时断网需要按事件产生速率和预期断网时长计算持久化容量，失去空间保护不得静默丢弃关键事件。

## 16.4 认证与版本矩阵

每个 `database × framework × deployment` 正式认证组合必须记录数据库大版本/驱动、节点故障域、同步复制/存储 HA 方案、RTO 实测、零已确认事务丢失证据、Worker 和 Outbox 的一致性测试及安全门禁结果。只有审核通过后才可从 `candidate` 进入 `certified`。

## 16.5 里程碑（不以日历承诺为依据）

- **M0：文档和 ADR 校验**：130 项 ADR 映射完整、规范结构与接口契约互相不冲突。
- **M1：技术可行性验证**：GraphQL 热切换、Kysely/dmdb、四库迁移和主库任务租约完成 PoC 与契约测试（须用户批准后才执行工程工作）。
- **M2：框架最小可靠闭环**：模块宿主、动作、事务/审计/Outbox、Worker、插件及最低权限的集成验证。
- **M3：可靠性与安全认证**：正式组合故障注入、离线补传、HA 恢复、插件/Agent 负向门禁。
- **M4：试点与发布治理**：运行指标与维护程序、版本兼容与升级、备份恢复演练、客户现场验收。

## 16.6 风险台账与退出条件

风险必须定义：类别、涉及 ADR、失败场景、影响、缓解/替代方案、验证负责人、测试证据、状态。特别对达梦方言、零已确认事务丢失的故障域覆盖、低信任插件隔离、跨版本 Schema 发布、主库任务可靠性维持 P0 跟踪。

**文档阶段完成判据：** 第 1～16 章、配套 ADR、契约和验收规范齐全；明确所有“待验证”的项目；没有隐性新决策或把假设伪装成已认证结果。文档齐备≠通过生产认证。


## 16.7 认证责任与证据链

每个测试案例应有负责团队、测试时间窗、被测数据库和驱动、部署模式、故障注入步骤、关键业务种子数据、预期结果与观察项。研发团队负责将事务/事件/插件等技术行为可测化，测试团队负责独立确认质量属性，交付团队负责在目标硬件和客户条件下执行部署演练。架构评审负责确认通过证据足以覆盖申请认证的组合。

对于真实四数据库，必须分别记录功能兼容状态与 HA 认证状态；使用某一库达到 RTO、零确认丢失不意味着另外三库自动通过。性能基准首次批准时应锁定环境与数据规模，后续硬件/数据库版本变化需决定是否重新建立基线。

## 16.8 进入实施阶段前的决策门槛

- ADR-001～130 均有清晰追踪且不被草案文档改变。
- 核心模块/动作/插件/事务/事件/任务契约已通过架构评审，关键错误与恢复路径没有责任悬空。
- P0 风险已有具体验证计划、判定标准和失败替代，不冒充测试成功。
- 完整规格、架构图、自动验收用例和文档风险台账经过检查，确认可以分阶段交给 Code Agent。
- 是否启动实际代码与 PoC，必须由用户在后续明确授权，不由本文自动触发。
