# 第 7 章 · 多数据库持久化与事务

**状态：** 规格草案。**关联 ADR：** 015、020、025、029、047、049、054～055、086、091～093、102、105、107、109～110、112～114、117～124、126～127、129。

## 7.1 数据归属与数据库适配

每个 MES 实例仅选择一个**主业务数据库**，正式支持目标 PostgreSQL、SQL Server、MySQL、达梦。每个客户企业独立部署；工厂本地库拥有生产事务权威。框架、官方插件应达到四库认证；客户插件可声明较小的数据库支持范围。

应用服务只依赖版本化 **Persistence Contract**，不得让数据库方言类型泄漏到业务动作或 GraphQL Schema。允许 ORM、Kysely 类型安全查询与受控 SQL 混用。Kysely 是优先工具；达梦通过 `dmdb` 验证自定义 Dialect，若失败按 ADR-123 切换受控 dmdb/SQL 适配，但仍保留四数据库正式支持目标。数据库实际版本、驱动和部署组合以认证清单为准。

## 7.2 契约能力矩阵（逻辑能力，非数据库产品通过结果）

必须定义并逐库认证：

- 事务：开始/提交/回滚、隔离级别、嵌套或保存点的支持声明、异常分类、提交结果不确定识别。
- 类型：Unicode、定点数、时间戳与时区、二进制、布尔表达、标识列、JSON 兼容方案、大对象、最大精度。
- 查询：分页、批量参数、排序确定性、参数化绑定、索引及锁行为；禁止任意字符串拼接 SQL。
- 迁移：版本记录、互斥、重复执行、校验、Expand–Migrate–Contract、在线兼容性以及非事务 DDL 的失败恢复。
- 任务和 Outbox：安全租约领取、持有者续约、锁定/版本比较、幂等唯一键、重试及死信隔离。
- 审计：关键业务事务记录与其数据变更、幂等记录及待发送 Outbox 事件在**同一数据库事务**提交。

## 7.3 关键事务提交序列

1. 服务端校验用户/Agent、动作权限、风险、审批有效期及资源版本。
2. 使用稳定业务请求 ID 查询幂等记录；相同键不同参数摘要为冲突，不得当作合法重试。
3. 在同一本地数据库事务内完成业务状态变化、关键审计、幂等执行记录、Outbox 事件（如适用）。
4. 只有已通过当前数据库部署等级的持久化路径确认后，才能向客户端返回已提交成功。
5. 如果连接在确认阶段中断，暴露 `UNKNOWN_COMMIT_STATUS` 并支持按稳定 ID 查询原事务结果，不自动重做。
6. 同步持久性保障失效时拒绝确认新的关键写入（ADR-119），允许安全的只读/非关键功能继续。

**不允许：** “数据库写入成功后再另发 MQ 消息并假定永不丢失”、审计失效但关键业务写入仍确认成功、为提升可用性而临时切至无保护单副本。

## 7.4 事务边界

- 默认模块自治，跨模块协调通过公开应用服务和业务事件实现；同数据库同事务上下文的可信模块，在确有必要时可共享本地事务。
- 隔离插件通过 API/消息编排而非共享 JDBC/SQL 连接事务参与；对非原子跨进程业务采用状态机、幂等和显式补偿。
- 外部设备或集团网络不纳入本地数据库提交锁域。

## 7.5 迁移及插件数据

- 迁移必须通过可读的计划/变更记录，支持前置数据库版本检查、对象所有权、权限最小化、向后兼容窗口和事后核验。
- 插件运行时凭据与迁移凭据分离；禁止把主库管理员权限交给客户插件。
- 破坏性迁移只能走受控维护窗口；代码回退不等于已迁移业务数据自动逆转。
- `databaseSupport` 必须在安装前声明并与认证矩阵匹配；禁止不兼容插件“带病运行”。

## 7.6 RPO、RTO 与故障验证

- **关键已确认生产事务**：在正式认证覆盖的故障域内目标零丢失；标准 RTO≤4小时、HA RTO≤15分钟。标准应用可单实例，但关键数据跨独立故障域同步持久化。
- **派生数据**：可丢失并由权威数据重建；权威非关键原始数据按单独业务等级规划，不推定同一 RPO。
- **高可用防脑裂**：仅单一权威写入；旧主隔离和仲裁前不可自动提升新主。MES 不自研数据库集群选主逻辑。
- 四库认证包含网络分区、单节点损毁、同步副本失效、提交响应丢失、切换中断及恢复核验，不能依赖厂商白皮书代替测试。

## 7.7 待验证风险

1. Kysely 对达梦 Dialect 的 Driver、QueryCompiler、DialectAdapter、DatabaseIntrospector、DDL 迁移锁能力覆盖，失败走 ADR-123 替代路线。
2. 四库在不同产品版本的行锁/租约、语句超时、事务隔离、数据类型语义差异。
3. 同步数据保护在电源损毁、网络分区和故障切换时是否仍能满足确认提交零丢失。
