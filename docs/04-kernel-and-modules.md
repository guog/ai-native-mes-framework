# 第 4 章 · 最小内核与模块体系

## 4.1 内核最小职责

本章描述**公开责任与约束**，不选具体 IoC 容器，也不要求现在编写实现。

框架内核只保留不可避免的装配与生命周期能力：

1. **模块清单与依赖图**：识别模块、公开版本、依赖关系及信任级别；静态依赖无环，非公开依赖不允许通过验证。
2. **模块注册表与生命周期**：基于显式清单初始化、就绪、启用、停用和错误状态；处理失败依赖的安全降级。
3. **公开能力注册**：以规范化方式连接可选技术模块提供的服务/动作/事件/GraphQL 扩展点，防止重复定义与命名冲突。
4. **必要运行时边界**：保证已停用模块不再获得新的公开调用，并协调在途请求与任务的安全结束。

**不直接纳入最小内核：** 完整生产订单逻辑、通用工业协议引擎、统一低代码解释器、模型推理、数据库 HA 选主器、自动管理所有客户插件的数据库实体。身份、权限、配置、审计、事件、任务、AI 适配可以是官方技术模块；这些能力在特定部署下可能是必要依赖，但这不等于全部属于不可拆分内核。

## 4.2 模块类别

- **内核**：运行时注册及生命周期的最小公共机制，非业务模块。
- **官方技术模块**：受版本化契约保护的身份权限、审计、配置、事务/事件、任务等能力。
- **官方业务模块（未来）**：单独演进的 MES 业务模块，不属于框架必须预置的技术底座。
- **可信项目模块**：通过严格评审可与宿主同进程；同进程代码视为充分可信，逻辑停用不承诺卸载 JS 模块。
- **客户/低信任插件**：按签名不可变包交付，独立进程/容器隔离，受管理员能力授权、数据库最小权限及前端 iframe 等边界保护。

## 4.3 公开契约及模块声明

模块必须公开声明：

- 唯一模块标识、版本、兼容的内核/SDK 范围和依赖。
- 对外公开的服务契约、事件、业务动作和 GraphQL Schema 所有权。
- 必要的数据所有权、可迁移数据库对象、目标数据库兼容范围。
- 可选的菜单/路由/UI 插槽及声明式展示配置。
- 后台任务处理器标识与版本、事件处理订阅和故障恢复要求。
- 对运行时所需资源与权限的能力声明；客户插件必须经明确授权。

**不得假定：** 文件具体名称/格式、运行时注册 API、包格式字段已经冻结。这些是第 5～6 章的后续契约规范，需在不修改 ADR 的前提下定义。

## 4.4 模块依赖纪律

- 静态依赖图必须无环。
- 模块只能访问其他模块的公开服务、动作和事件；不得 import 内部文件或直接查询其他模块私有表。
- 模块可通过公开服务接口同步调用；可靠跨模块协作可通过事件完成。
- 同数据库、同事务上下文的**可信模块**，确有必要时可以通过公开契约共享本地事务；默认优先模块自治与编排。
- 独立隔离插件通过 API/消息/协调调用，不作为同一主数据库连接的共享事务参与者。

模块依赖边界需要在 CI 中静态校验，并结合安装时依赖与版本验证。

## 4.5 生命周期契约

一个模块在公开视角下至少有：`discovered / validated / installed / ready / active / draining / disabled / failed` 等可观察状态。这些**状态名称是规格草案建议**，并非已批准的运行时枚举或固定状态机；实现前必须经过插件契约规范细化。

已确认的强制行为：

- 安装前验证签名、来源、依赖、版本和能力授权；Schema 冲突、兼容性不匹配必须拒绝激活。
- 同进程可信插件支持不停机逻辑启停，但不保证彻底卸载代码；升级可以受控维护窗口。
- 停用先拒绝新业务请求和新任务领取，在途动作完成或安全中止，长任务保存检查点。
- 旧任务记录处理器版本，恢复前验证兼容性，禁止直接丢弃队列。
- 失败插件及依赖功能安全降级；其余无关能力继续运行。
- GraphQL 新 Schema 经校验后以版本化快照发布，原子切换；高可用实例短时兼容共存。

## 4.6 模块运行时失败案例

- **Schema 命名重复**：安装验证阶段拒绝激活；不能以“后注册覆盖先注册”解决。
- **插件启动失败**：保持其他模块可用，错误被追踪并标记依赖链；不允许部分激活后绕过授权。
- **数据库迁移无法预检**：拒绝热安装；破坏性变更只能在已获批准的受控维护窗口执行。
- **插件停用但 GraphQL 字段处于兼容期**：保留结构并返回明确不可用错误，绝不继续执行停用业务动作。
- **长任务处理器版本不匹配**：暂停领取并进入兼容性/恢复流程，禁止错误处理器直接消费旧任务。

## 4.7 AI Native 工程契约

- Code Agent 修改任何模块必须遵守公开契约及无环依赖；公开动作/schema/迁移变更应关联相应测试。
- AI 生成新模块不等于可以自动进入生产：测试、审查、签发和授权人员批准是独立强制门禁。
- 代码库应包含机器可读模块规格、架构规范、测试要求和 Agent 工作指引；具体规范在第 14 章细化。

## 4.8 本章尚待补充的定义

- 依赖图/Schema 冲突的自动测试规则。
- 可信同进程模块热加载的可管理资源清单与实现限制。
- 隔离插件通信和权限能力表达方式。
