# 第 3 章 · 系统总体架构

## 3.1 总体设计

架构由工厂本地 MES 核心、官方可选技术模块、受限插件执行环境、独立 Worker、独立 AI Runtime、工业网关和集团共享数据层构成。

**运行主体：**
- **MES API/Host**：Node.js/TypeScript，Fastify + GraphQL Yoga + GraphQL Tools；根据各模块公开契约组织 GraphQL Schema 和 REST/MCP 适配入口。
- **最小内核**：模块清单、依赖检查与生命周期；公开契约注册与必要的运行时控制。业务动作执行语义由统一动作契约及受控服务定义；具体技术模块边界见第 4 章。
- **官方技术模块**：身份认证、授权、审计、持久化任务、事件/Outbox、配置、插件管理和可选 AI 接入等。在需要的部署模式下按能力依赖组合。
- **业务扩展**：可信业务模块可与宿主同进程；客户/低信任插件隔离进程或容器运行，不允许直接访问主进程内部私有对象。
- **Worker**：从主业务数据库持久化任务机制中安全领取任务；可与 MES 同机部署但作为独立执行进程。
- **AI Runtime**：拥有 Agent 编排与检查点；只通过动作目录与统一业务动作执行入口访问生产业务；AI 不可用不应使核心生产事务失效。
- **工业集成**：OPC UA/MQTT/设备协议适配器或边缘网关独立；高频设备写入使用独立通道。
- **集团数据层**：通过异步业务事件/显式数据变更契约、指令和快照与工厂交互；不拥有工厂实时生产事务直接提交权。

## 3.2 数据平面与控制平面

### 数据平面

- 业务写入以工厂本地数据库为权威。
- 关键事务与关键审计及 Outbox 待发事件同事务提交。
- 通过 Outbox 和可靠异步消息向集团/其他服务发布数据；接收端持久化幂等状态与必要顺序。
- 数据库 HA 或可靠存储基础设施保障跨故障域持久性；生产动作提交前不请求集团确认。

### 控制平面

- 控制模块/插件生命周期、能力注册、信任授权、Schema 版本切换、后台任务版本及生产发布审批。
- 集团侧可以提出业务指令；工厂本地校验并决定接受/拒绝，然后在本地事务中执行。
- 身份与配置变更需本地缓存及离线保障；敏感变更受控发布和审计。

## 3.3 GraphQL 与业务动作关系

GraphQL 是主要业务 API，但通信协议不承载最终业务规则。框架统一维护 TypeScript + Zod 的业务动作契约，声明输入输出、授权、风险、版本、幂等、审批等信息。GraphQL Mutation、REST 与 MCP 只作为适配入口；GraphQL 查询通过显式查询契约和受控读取服务访问数据，绝不自动把 ORM 实体无限制暴露。

每个模块声明自己的 Schema 与 Resolver，由宿主进行命名所有权和兼容检查；发布新版本化 Schema 快照并原子切换。多实例可有短期兼容窗口；停用插件后兼容期可以保留字段，但调用必须返回明确不可用错误。

## 3.4 部署模型

### 单工厂

工厂持有独立业务库和 MES Host/Worker，并具备本地认证授权；AI Runtime 和可选组件按需部署，离线核心生产功能不依赖 AI 或集团服务。

### 集团化

各工厂实例拥有自己的生产事务数据库；集团层持有共享数据及指令/身份管理。集团共享数据库按工厂隔离，但不是工厂实时生产写事务的唯一数据库（ADR-008 适用范围经 ADR-022 明确）。

### 标准与高可用

- 标准：可使用单应用实例；关键生产数据仍需跨独立故障域同步持久化；允许人工恢复，RTO ≤ 4 小时。
- 高可用：覆盖工厂内部单应用、服务器及数据库节点故障，RTO ≤ 15 分钟；需确保单权威写入、仲裁/Fencing。机房灾难不在该等级的默认 HA 范围。
- 必须分别对数据库×框架版本×部署方式执行认证，不能用本逻辑图代替拓扑验收。

## 3.5 关键场景

1. **关键业务写入**：用户/Agent -> 入口适配 -> 业务动作执行服务 -> 授权/审批/版本/幂等 -> 同事务提交业务、审计和 Outbox -> 持久性确认后返回。
2. **集团指令**：集团投递指令 -> 工厂持久化接收及去重 -> 工厂本地校验并接受/拒绝 -> 业务执行结果异步反馈。
3. **插件停用**：阻止新调用与任务领取 -> 处理在途操作及检查点 -> 撤销运行权限/资源 -> 切换兼容 Schema 快照 -> 保留相关数据和任务历史。
4. **长时离线**：继续工厂本地生产，事件积压监控 -> 连接恢复后按检查点补传 -> 校验去重/必要顺序 -> 对账或快照修复。
5. **Agent 操作**：Agent 发现按身份过滤的动作 -> 请求受控执行 -> MES 重新检查授权和业务状态 -> 产生事务、审计及可追踪结果。

## 3.6 故障边界

- AI Runtime 故障：核心 MES 可以退化为常规查询/生产功能；关键事务不依赖模型。
- 隔离插件崩溃：只关闭依赖它的功能，其他无关能力继续。
- 集团断网：工厂本地用户仍可认证并完成生产，消息积压后恢复。
- 数据库同步持久化条件失效：不得确认新关键生产写入，安全查询可继续。
- Worker 崩溃：任务至少一次执行、租约恢复和处理器幂等；不承诺外部副作用 exactly-once。
