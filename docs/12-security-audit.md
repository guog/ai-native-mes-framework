# 第 12 章 · 身份、安全与审计

**状态：** 规格草案。**ADR：** 018～019、026、036、039、041～044、048、052、055～056、062、067、072、077、083～084、095、097、109～110、130。

## 12.1 安全模型

所有授权判定使用服务端可信身份上下文：**主体（用户/服务/Agent/插件）× 资源（含工厂）× 动作 × 环境/授权状态**。RBAC 是基础，业务动作风险策略、审批、委托期限及插件能力声明属于额外边界。客户端 GraphQL 变量、iframe 消息或 Agent 提示词中的工厂 ID 不得成为信任依据。

- 统一的访问控制由身份/权限技术模块提供，读取 Query 和写入 Action 均须校验；跨模块链路传递签发的、可追踪的权限上下文。
- 对多工厂的集团共享层进行工厂粒度的数据隔离。不同客户企业独立部署，不把客户之间复用同一实例当作已确认目标。
- 本地工厂保存离线可验证身份及权限版本、有效期。中心撤销因离线暂不能到达时，本地管理员有紧急撤销路径，中心变更联网后同步。

## 12.2 插件信任及最小权限

- 插件签名、发布者验证和审批不能替代沙箱及运行时权限。低信任插件独立隔离，限制文件系统、网络、CPU/内存、数据身份与可执行能力。
- 数据迁移身份与业务运行身份分离；生产关键业务表不应被插件直接写入，必须通过受控应用动作执行。
- 授权和资源能力必须可撤销，撤销后阻止新的业务写入/任务领取；已执行事务按业务补偿而非盲目回滚。

## 12.3 密钥与配置

- 类型化分层配置，敏感凭据与普通可审计配置分离。普通展示配置可以按权限动态覆盖，密钥与关键安全配置必须经过受控发布。
- 离线工厂需要可用的本地机密保护方案，不以集团中心网络作为关键事务运行依赖。
- 密钥不得进入插件 Manifest 明文、UI 前端资源、日志或 AI 工具返回值。签名、凭据及授权应具备可轮换方案。

## 12.4 审计与追踪

- 关键业务提交、动作执行记录、授权决策结果及必要审计证据同本地事务持久化；诊断日志可异步降级。
- 审计记录至少关联 `correlationId`、`requestId`、发起人/Agent/插件身份、实际资源与工厂、动作及版本、审批/委托引用、执行结果、时间及执行节点。
- 日志内容不得包含不必要的敏感生产数据或密钥。审计具有完整性保护、最小查看权限、留存与导出策略；具体留存期须按客户合同与法律规范确定，不擅自指定统一天数。
- 工厂事件向集团汇聚采用异步可靠通道，不依赖集团在线才能完成本地关键提交。

## 12.5 强制负向验收

- 未授权账户修改另一个工厂的数据；通过 GraphQL 嵌套 Query 绕过字段授权；在 UI 切换工厂时复用旧权限；伪造同步源身份。
- 插件以非关键数据身份直接写入关键业务表；插件停用后旧任务继续触发新动作；资源超配额后影响宿主。
- Agent 使用已撤销或过期令牌、超出审批范围调整参数、使用旧资源版本、重复提交关键生产动作。
- 审批失效或审计存储不可用时，关键业务动作不应“成功但无可恢复证据”。

**验收标准：** ADR-130 负向用例进入 CI/发布门禁；结果记录应包含可追溯的相关 ID、预期拒绝及实际证据。


## 12.6 审计证据的不可抵赖边界

审计至少区分请求发起、策略判定、实际提交结果与外部同步结果。单条关联日志不能证明事务已提交；关键审计应存储于与业务状态同一权威事务边界。异步导出至集团或集中日志平台可延迟，但不得替代本地审计证据。审计写入失败时，关键业务不可“成功且没有审计”；对于仅诊断用的日志，可降级并监控容量。

管理员可以查看和导出审计，不代表可以改写已经提交的审计记录。审计的数据完整性保护、最小权限访问、保存与清理需要经客户制度与适用要求确定，并在存储隔离、备份、时钟和可追踪性方面建立证据，不应在未制定制度时擅自承诺固定留存期限。

## 12.7 威胁建模及发布门禁

每类公开扩展面至少覆盖身份冒用、Schema 注入/资源耗尽、跨工厂访问、客户插件进程逃逸、缓存泄漏、AI 工具权限放大、审批请求重放、失效授权持续执行、日志/模型泄密、迁移凭据滥用。正式发布检查同时审查技术依赖来源、签名及升级路径。失败插件不得让受影响业务在缺少必要校验的情况下退化为“允许所有请求”。
