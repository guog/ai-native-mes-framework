# 第 5 章 · 动态插件与隔离运行架构

**阶段：** 规格草案，未经实现验证。**约束依据：** ADR-009、017～018、024～025、032～034、042～045、048、055、059～062、078～083、088～089、093、096、104～105、110～111、130。

## 5.1 范围与模型

插件是独立演进、受版本和能力约束的扩展交付单元，不等同于任意 JavaScript 动态导入。框架拥有插件目录、依赖检查、签名核验、生命周期、权限授予、GraphQL 发布、UI 注册、任务处理器注册、数据库迁移和审计。插件只拥有声明的业务数据与公开能力，不得直接修改核心模块私有表。官方模块和内部可信模块仍受公开契约限制。

- **可信同进程扩展**：经明确的组织信任判定可共享宿主进程；采用逻辑停用，移除入口和可管理资源，不承诺彻底卸载 JavaScript 依赖。升级允许维护窗口。
- **客户及低信任扩展**：独立进程/容器运行，资源、网络、文件、数据库身份单独限制；与主宿主通过受控 API、事件或任务边界通信。隔离并不使恶意扩展“安全”，必须结合权限及负向测试。
- **前端 UI**：可信扩展通过统一 Vue 壳的路由/菜单/槽位装配；低信任 UI 使用隔离文档及受控消息协议，禁止共享高权限令牌。

## 5.2 不可变发布单元

签名发布包的规范性清单至少声明：`pluginId`（全局稳定）、`version`（不可变）、`publisher`、`artifactDigest`、`signature`、`trustClass`、`sdkRange`、`hostRange`、`databaseSupport`、`dependencies`、`capabilitiesRequested`、`serviceContracts`、`graphqlExports`、`actions`、`events`、`uiSlots`、`taskHandlers`、`migrations`、`configurationSchema`。字段名及序列化格式属于 **草案契约**，不得视为已批准代码 API。

- 签名验证同时校验发布者信任策略、完整性、版本及重放风险；签名只证明来源，不隐含授予全部能力。
- 标识与版本唯一。相同 `(pluginId,version)` 内容摘要不同必须拒绝。
- 所需能力由管理员显式授权，授权可撤销；插件重新签发或升权要求重新评审。运行时按插件身份约束资源。
- 验证完毕前不得向 GraphQL、任务、前端或动作目录公开插件入口。

## 5.3 安装、启用、停用、升级状态机

**建议的可观察状态**：`discovered → verified → staged → migrating → ready → active → draining → disabled`，异常为 `blocked/failed`。这是设计细化草案，不是 ADR 修改。

1. **安装前**：校验签名、散列、依赖 DAG、版本窗口、数据库支持、权限声明、迁移计划、Schema 命名/所有权和可回滚/恢复前提。
2. **Staging**：先准备隔离进程及资源配额；数据库兼容性迁移允许受控热安装，破坏性迁移只在批准维护窗口执行。任何失败维持此前活跃版本。
3. **激活**：动作/Schema/Resolver/UI/Worker 处理器作为一个发布代际 (`generation`) 进行一致性登记。准备好新的版本化 Schema 快照并校验，单实例原子切换，多实例逐步报告就绪且允许兼容窗口。
4. **停用**：首先撤销新请求、新任务领取、新动作执行许可；进入 draining。等待在途本地事务完成或依安全规则中止，持久任务保存检查点；兼容期内 GraphQL 字段可保留但应返回明确“功能不可用”错误，不能调用已停用能力。
5. **升级**：保持旧任务记录的处理器版本；旧任务必须通过兼容处理器、状态迁移或安全暂停恢复，禁止交给不兼容新处理器盲目执行。触及数据破坏性变化需要维护窗口和已批准备份/修复方案。
6. **失败**：失败插件依赖的功能 fail closed；无关模块继续运行。原版本回退仅在数据库兼容且权限允许时进行。

## 5.4 插件隔离与数据所有权

- 插件仅拥有自己的命名对象；禁止以同一个主库管理员身份执行客户业务 SQL。数据迁移凭据与运行凭据分离，运行身份只具有明确授权的私有数据操作权。
- **关键生产状态**写入必须经过受控业务动作（授权、规则、事务、审计、幂等）。拥有某张私有表不自动意味着能绕过该规则。数据库角色/写入路径必须实际阻断该绕过。
- 同进程可信模块在同库同事务上下文下才可经公开契约参与本地共享事务；隔离插件不得被假定为同连接事务参与者。
- 资源限制包括 CPU/内存、文件系统、网络目的地、任务并发、日志大小、连接池和调用超时；需要运行时可观测与强制执行，单纯 Manifest 声明不足。
- 隔离插件无法依赖 Node.js 同进程 VM 获得强安全保证；实际隔离由操作系统进程/容器及平台权限完成。

## 5.5 SDK 兼容与安全契约

- 稳定公开契约允许按版本演进，插件包必须声明最低/最高支持范围。未在认证窗口内的组合不得激活。
- 核心内部模块实现、私有数据库表和内部 DI 注册不得成为 SDK 公开能力。
- 插件被暂停或授权撤销时，GraphQL 入口、事件处理和后台任务领取全部进行运行时重新检查；此前缓存的工具发现信息不可替代执行时验证。
- 前端 iframe 消息携带严格来源校验、允许的消息类型和会话范围；不将数据库凭据、管理员令牌传入低信任前端。

## 5.6 验收场景

- **PLG-01** 不可信签名或包散列变化 → 安装拒绝，原 Schema/任务不变。
- **PLG-02** 缺少模块依赖、SDK 超范围、GraphQL 命名冲突 → 激活拒绝。
- **PLG-03** 插件停用期间存在进行中事务/任务 → 新入口阻断、在途安全完成/检查点，不丢失已提交状态。
- **PLG-04** 插件崩溃或越限资源访问 → 故障隔离，敏感能力不可调用，其他业务模块保持运行。
- **PLG-05** 低信任插件尝试越权读其他工厂、跨插件表或绕过关键业务动作写表 → 拒绝并记录安全证据。
- **PLG-06** Schema 跨实例滚动切换与回退 → 兼容窗口内旧客户端操作按发布契约可执行或返回明确错误，不出现执行到错误插件代际。

**需进一步验证：** 四库最小权限能力、代码包的隔离资源配额、GraphQL 快照在高可用节点的发布语义、长期任务版本迁移；技术未验证前不得宣称已实现。
